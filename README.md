# Система контроля строительной техники

Локальное веб-приложение для анализа фотографий строительной площадки. Пользователь задаёт план техники на выбранную дату, загружает снимки, а модель YOLO определяет типы и количество техники. Результаты сохраняются в SQLite и отображаются в виде истории, сравнений «план / факт» и графиков по времени.

## Возможности

- создание проекта и планов техники по датам;
- выбор количества каждого вида техники;
- загрузка нескольких JPG/PNG в одну дату проекта с указанием времени снимка;
- распознавание строительной техники моделью YOLO;
- сохранение результата и фотографии в локальную базу;
- сравнение запланированного и обнаруженного количества;
- предупреждения о недостающей и непредусмотренной планом технике;
- графики изменения количества техники по времени;
- повторный просмотр любого сохранённого анализа.

> «Техника не обнаружена на снимке» не означает, что её физически нет на площадке: объект может находиться вне кадра или не распознаться моделью.

## Поддерживаемая техника

Модель и интерфейс используют одинаковые 6 классов:

| ID | Класс модели | Название |
|---:|---|---|
| 0 | `excavator` | Экскаватор |
| 1 | `dump_truck` | Самосвал |
| 2 | `wheel_loader` | Фронтальный погрузчик |
| 3 | `motor_grader` | Автогрейдер |
| 4 | `concrete_mixer` | Автобетоносмеситель |
| 5 | `mobile_crane` | Автомобильный кран |

## Технологии

### Frontend

- **Next.js 16.1.6** - React-фреймворк и локальный прокси к API;
- **React 19.2.3** - пользовательский интерфейс;
- **TypeScript 5** - типизация frontend-кода;
- **Tailwind CSS 4** - стили;
- **Bun 1.4+** - установка JavaScript-зависимостей, запуск и тесты;
- **Biome 2.2** - форматирование и статическая проверка кода.

### Backend и машинное обучение

- **Python 3.11**;
- **Flask 3.1.2** - HTTP API;
- **Waitress 3.0.2** - локальный WSGI-сервер;
- **SQLite** - проекты, планы и результаты проверок;

- **PyTorch 2.7.1** и **Torchvision 0.22.1**;
- **Pillow 11.3** - чтение и проверка изображений.

## Архитектура

```text
Браузер
   │
   ▼
Next.js / React :3000
   │  /api/* (rewrite)
   ▼
Flask / Waitress :8000
   ├── YOLO best.pt
   ├── SQLite equipment.db
   └── фотографии equipment_evidence/
```

Frontend отправляет запросы на `/api/*`. Правило в `next.config.ts` пересылает их на `http://127.0.0.1:8000`.

## Системные требования

- Windows 10/11;
- Python 3.11;
- Bun 1.4 или новее;
- примерно 5 ГБ свободного места для Python-окружения и ML-библиотек;
- GPU не обязателен: по умолчанию сервер использует CPU;
- для GPU требуется совместимая NVIDIA-видеокарта и установленный драйвер.


## Установка

Все команды выполняются из PowerShell.

### 1. Распаковать или клонировать проект

```powershell
cd "путь\к\NOVA-AI"
```

### 2. Установить frontend-зависимости

```powershell
bun i в папке с проектом
```

### 3. Создать Python-окружение backend

```powershell
cd server
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
```

> Установка PyTorch может занять несколько минут. `requirements-lock.txt` содержит CUDA 12.8-сборку, которая также поддерживает запуск inference на CPU.


## Запуск

Нужны два окна PowerShell.

### Окно 1 - backend

```powershell
cd "путь\к\NOVA-Ai\server"
python.exe server.py --weights best.pt --database equipment.db --port 8000
```

Успешный запуск:

```text
Weights: ...\best.pt
Database: ...\equipment.db
API ready: http://127.0.0.1:8000
```

Проверка backend:

```powershell
curl.exe http://127.0.0.1:8000/health
```

Ожидается:

```json
{"status":"ok"}
```

### Окно 2 - frontend

```powershell
cd "путь\к\NOVA-Ai"
bun run dev
```

Откройте в браузере:

```text
http://127.0.0.1:3000
```

Оба окна должны оставаться открытыми. Остановка - `Ctrl+C` в каждом окне.


## Настройка

### Параметры backend

```powershell
.\.venv\Scripts\python.exe server.py `
  --weights best.pt `
  --database equipment.db `
  --port 8000 `
  --device cpu `
  --conf 0.25
```

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `--weights` | `best.pt` | путь к весам YOLO |
| `--database` | `equipment.db` | путь к SQLite |
| `--port` | `8000` | порт API |
| `--device` | `cpu` | `cpu` либо `0` для первой NVIDIA GPU |
| `--conf` | `0.25` | минимальная уверенность детекции, от 0 до 1 |

Пример запуска на NVIDIA GPU:

```powershell
python.exe server.py --device 0
```

Если меняется порт backend, обновите адрес `destination` в `next.config.ts`, после чего перезапустите Next.js.

### Замена модели

1. Остановите backend.
2. Сохраните старый `best.pt` для возможности отката.
3. Положите новые веса рядом с `server.py` или укажите путь через `--weights`.
4. Запустите backend заново.
5. Проверьте `/health` и известную фотографию.

Новая модель должна содержать те же 6 классов в том же порядке. Сервер намеренно откажется запускаться, если список классов не совпадает.

## Пользовательский сценарий

### Создание даты

1. Откройте «Создать дату».
2. Введите название проекта.
3. Выберите дату.
4. Укажите количество техники.
5. Нажмите «Сохранить дату и перейти к фото».

Если указать существующее название проекта, дата добавится к нему. Повторное сохранение той же даты обновляет план, но не изменяет старые анализы.

### Загрузка фотографии

1. На главной странице выберите запись `дата - проект`.
2. Выберите JPG/PNG.
3. Укажите время снимка.
4. Нажмите «Проверить и сохранить».

Ограничения загрузки:

- только JPG/PNG;
- максимум 10 МиБ на запрос;
- максимум 20 мегапикселей.

### Просмотр результатов

На странице «Результаты и графики» выберите `дату - проект`. Доступны:

- количество сохранённых проверок;
- последняя проверка;
- график выбранного вида техники по времени;
- таблица истории;
- сравнение плана и результата;
- предупреждения;
- сохранённое фото-доказательство.

## API

Основные endpoint-ы:

| Метод | URL | Назначение |
|---|---|---|
| GET | `/health` | состояние backend |
| GET | `/projects` | список проектов |
| POST | `/projects` | создать проект |
| GET | `/projects/{id}/plans` | даты проекта |
| GET/PUT | `/projects/{id}/plans/{YYYY-MM-DD}` | получить/сохранить план |
| POST | `/projects/{id}/observations` | загрузить фото и сохранить анализ |
| GET | `/projects/{id}/report` | история и данные графиков |
| GET | `/evidence/{filename}` | сохранённое фото |

Frontend обращается к этим endpoint-ам через префикс `/api`, например `/api/projects`.
К ии на сеервере можно делать запросы, например:

```powershell
curl.exe -F "file=@D:\путь\фото.jpg" http://127.0.0.1:8000/detect
```
В ответе будет указан тип распознанной техники


## Ограничения прототипа

- поддерживаются только перечисленные 6 классов;
- ИИ часто допускается ошибка, из-за нехватки датасетов и времени на обучение 
- бульдозеры, катки и другие классы пока не распознаются;
- анализируется отдельная фотография, а не видеопоток;
- приложение не отслеживает уникальные машины и не фиксирует въезд через ворота;
- количества на разных снимках не суммируются;
